# Inbox part 2 (the look and the message fixes) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Inbox and the lead page's chat read like WhatsApp and stay compact on a phone: formatted bubbles, photos
that never move the chat, a one-line AI strip, a one-row reply box, a compact list with two-line rows, and the messages
that looked broken explained or fixed.

**Architecture:** Web changes in `apps/web/src/inbox` and `apps/web/src/ai`; one contract field (`handedOver` on a list
row) computed in `packages/domain/src/inbox/views.ts`; item 12 touches the MSG91 parser, `process-event.ts`, the
inbox health job and one additive migration. Two lines of work run in parallel worktrees: **A, the chat** (Tasks 1-6)
and **B, the list and the server** (Tasks 7-10, branched from A after Task 1, which B's rows use).

**Tech Stack:** Next.js 16.4 (never `next upgrade`), React 19, Tailwind v4, shadcn radix-nova registry, next-intl,
TanStack Query + tRPC, Vitest + Testing Library, Playwright journeys, Prisma 7.10 on Postgres.

**Spec:** `docs/superpowers/specs/2026-11-22-inbox-revamp-design.md`, part 2, items 7-15 (items 10, 11, 13-15 updated
with the owner on 2026-11-24). Read it before your task.

## Global Constraints

- `CLAUDE.md` binds every task: registry components only; no `border`/`divide-`/`ring-`/`shadow` classes outside
  `components/ui`; brand tokens only; every word in the feature's messages file (`inbox.json`, `ai.json`); 44px touch
  targets; test first; strict TypeScript (no `any`, no `!`); ~200 lines per file is a smell.
- Message text is rendered as React elements, never HTML (`dangerouslySetInnerHTML` is forbidden).
- The AI is called "the AI" in the Inbox, never by the name it signs with.
- What shrinks on a phone is the number of rows, never a touch target below 44px.
- Logs carry ids, codes and counts only; job data holds ids.
- Commits: small Conventional Commits, lowercase subject, header ≤ 100 characters, files staged by name, never
  `git add -A`, no `Co-Authored-By`, never push. Shell commands start with `source ~/.nvm/nvm.sh && nvm use >/dev/null &&`.
- Least code that meets the need (owner): no new abstraction a single use doesn't need.

## Review Focus

1. Text that looks like markers but isn't: `2*3*4`, `file_name_v2.pdf`, a link with `_` or `*` in it, an email; it
   reads exactly as typed and links still open (Task 1).
2. Unbalanced or crossing markers: a lone `*`, `*bold _both*_`, a marker pair split across two lines; nothing
   breaks and no character is lost (Task 1).
3. Hindi and emoji next to markers (`*नमस्ते*`, `*Manali 🏔️*`): formatted, and the bubble keeps `dir="auto"` (Task 1).
4. A very tall photo, a very wide one, and one whose file fails to load, on a 320px screen: the frame never changes
   size and the page never scrolls sideways (Task 2).
5. A long hand-over reason in the one-line strip, and Note chosen in a chat with no lead: the line truncates but opens
   in full; Note is offered disabled with the existing "no lead yet" sentence (Tasks 4, 5).
